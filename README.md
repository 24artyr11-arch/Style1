# Гардероб — Telegram-бот

Telegram-бот распознаёт вещи пользователя, подбирает из них комплекты, создаёт единое каталожное
изображение образа и по желанию показывает виртуальную примерку на фотографии пользователя.

## Что реализовано

- Личные чаты доступны всем пользователям без отдельного экрана согласия.
- Фото вещи при загрузке отправляется только на распознавание категории, точного типа и признаков.
- Отдельное обработанное изображение для каждой вещи больше не генерируется.
- Оригинальное нормализованное фото сохраняется в гардеробе.
- Несколько фотографий одним альбомом обрабатываются по очереди для одного пользователя.
- Гардероб поддерживает просмотр, страницы, исправление категории и удаление.
- В интерфейсе не показываются внутренние номера вещей.
- Подбор учитывает температуру, погоду, повод, стиль и цвета.
- ИИ выбирает от одного до трёх комплектов только по ID реально существующих вещей.
- Для каждого готового комплекта выполняется один Image Edit запрос сразу со всеми фотографиями вещей.
- Полученное изображение образа сохраняется и повторно открывается без нового платного запроса.
- Пользователь может загрузить отдельную фотографию в полный рост и примерить сохранённый образ.
- Результат примерки также кэшируется. При замене фото человека или вещи кэш сбрасывается.
- Ручная замена вещи создаёт новое изображение только для изменённого образа.
- Последние три образа доступны после перезапуска; в базе хранится до 30 образов на пользователя.
- Разные пользователи обрабатываются параллельно, а действия одного пользователя сохраняют порядок.
- Все данные пользователя можно удалить из меню.

## Как теперь расходуются запросы

### При загрузке вещи

Выполняется один запрос к vision-модели для распознавания. Image API не вызывается.

### При создании образа

Сначала текстовая модель выбирает вещи, затем для каждого предложенного комплекта выполняется один
запрос к Image Edit API со всеми фотографиями этого комплекта.

### При виртуальной примерке

Image Edit API получает первым референсом фото пользователя, затем фотографии вещей выбранного
образа. Запрос выполняется только после нажатия «Примерить на себе».

Такой поток убирает дорогую генерацию для вещей, которые пользователь может никогда не включить
в образ, и не повторяет генерацию при обычном просмотре сохранённого результата.

## Изображение образа

`OUTFIT_IMAGE_PROMPT` в `bot.py` требует:

- вертикальный холст 1024×1536 и белый фон;
- использование каждой переданной вещи ровно один раз;
- сохранение цвета, принта, кроя, длины и деталей;
- удаление людей, рук, вешалок и исходных фонов только в итоговом изображении;
- верхние слои в общей верхней зоне с одинаковой визуальной шириной;
- длинный низ примерно на 40–44% высоты холста;
- обувь примерно на 12–15% высоты;
- меньший масштаб сумок и аксессуаров;
- отсутствие текста, манекена, новых предметов и декоративных элементов.

В Image API несколько референсов передаются повторяющимся multipart-полем `image[]`.
Готовый результат запрашивается как JPEG с качеством 90: прозрачность здесь не нужна, а передача
обычно быстрее и компактнее PNG.

## Виртуальная примерка

В главном меню выберите «Фото для примерки» и отправьте одну фотографию, на которой:

- человек виден в полный рост, от головы до обуви;
- поза прямая;
- руки не закрывают одежду;
- освещение ровное;
- нет сильного размытия.

Фото сохраняется отдельно от гардероба. Его можно заменить или удалить. При полной очистке данных
оно также удаляется.

Генеративная примерка является визуальной оценкой, а не гарантией фактической посадки или размера.

## Параллельная обработка

Long polling работает в основном потоке. Полученные обновления передаются в `UpdateDispatcher`:

- для каждого пользователя создаётся собственная последовательная очередь;
- разные пользователи выполняются одновременно в `ThreadPoolExecutor`;
- число параллельных пользовательских очередей задаёт `WORKER_COUNT`;
- SQLite защищён общей блокировкой и работает в режиме WAL.

Значение по умолчанию — четыре worker-потока. Для одного небольшого сервера обычно достаточно
`WORKER_COUNT=4`. Слишком большое значение может быстро исчерпать лимиты OpenAI или Telegram.

## Быстрый запуск

Понадобится сервер с Docker Compose, исходящим HTTPS-доступом к Telegram и OpenAI, токен Telegram-бота
и API-ключ OpenAI с доступом к указанным моделям.

1. Скопируйте `.env.example` в `.env`.
2. Заполните `TELEGRAM_BOT_TOKEN` и `OPENAI_API_KEY`.
3. При необходимости настройте модели и `WORKER_COUNT`.
4. Если бот уже запускался, сохраните прежнее имя Docker volume в `WARDROBE_VOLUME_NAME`.
5. Запустите:

```bash
docker compose up -d --build
docker compose logs --tail=50 bot
```

После изменения `.env`:

```bash
docker compose up -d --build --force-recreate
```

База находится в именованном Docker volume. Не используйте `docker compose down -v` и не удаляйте
volume вручную, иначе гардеробы будут потеряны.

Бот использует long polling. Домен и открытые входящие порты не нужны. Не запускайте одновременно
другой процесс с тем же Telegram-токеном. При обнаружении активного webhook программа завершится.

## Обновление существующей базы

Миграция выполняется автоматически:

- добавляется таблица с фото пользователя;
- к сохранённым образам добавляются поля готового изображения и примерки;
- старая таблица, использовавшаяся только для согласия, удаляется;
- прежние оригиналы и гардеробы сохраняются;
- старые каталожные версии вещей остаются в legacy-поле, но больше не используются;
- старый образ без сохранённой картинки генерируется один раз при первом открытии.

Перед обновлением рабочего сервера рекомендуется сделать резервную копию
`/data/wardrobe.sqlite3`.

## Первая проверка

1. Добавьте минимум три верха, один низ и одну пару обуви.
2. Убедитесь, что при загрузке бот быстро распознаёт вещь и показывает исходное фото.
3. Нажмите «Подобрать образы» и ответьте на пять вопросов.
4. Проверьте сгенерированные вертикальные изображения и пропорции вещей.
5. Замените одну вещь и убедитесь, что изменился только выбранный образ.
6. Добавьте фото в полный рост и нажмите «Примерить на себе».
7. Одновременно начните обработку с другого Telegram-аккаунта: второй пользователь не должен ждать
   завершения первого.

## Данные и безопасность

Фото и результаты хранятся BLOB-ами в SQLite `/data/wardrobe.sqlite3`. Изоляция выполняется по
Telegram ID во всех запросах, включая callback-кнопки.

В OpenAI передаются:

- фото вещи для распознавания;
- фото выбранных вещей для изображения образа;
- фото пользователя и выбранных вещей для виртуальной примерки.

Для Responses API установлено `store=false`. Секреты и фотографии не выводятся в журнал.
`.env` исключён из Git и Docker image.

Удаление данных на сервере бота не удаляет сообщения и исходные фотографии из Telegram, а также
данные, которые внешние провайдеры хранят по своим правилам. База SQLite не зашифрована, поэтому
доступ к серверу и диску должен быть ограничен.

## Ограничения

- Генеративная модель может немного изменить мелкие детали вещи, несмотря на строгий промпт.
- Проверки реального человека в фото для примерки без дополнительного AI-запроса нет.
- Один процесс с worker-потоками подходит для MVP, но не заменяет распределённую очередь задач.
- SQLite сериализует операции с базой, хотя сетевые AI-запросы выполняются параллельно.
- Нет автоматического лимита расходов, пользовательских квот и автоматических резервных копий.
- Update отмечается обработанным до выполнения. После аварийной остановки пользователь может
  повторить действие, зато платный запрос не запускается автоматически второй раз.
- До 200 вещей на пользователя. Фото нужно отправлять как фотографии, не как документы.
- Ручная замена ограничена той же широкой категорией и не проходит повторную проверку стилистом.

## Разработка и тесты

Требуются Python 3.12+ и Pillow.

```bash
python -m pip install -r requirements.txt
python -m unittest discover -s tests -v
```

Тесты используют подставные Telegram/OpenAI и не выполняют платных запросов. Они проверяют
распознавание без генерации, создание образов, примерку и кэш, изоляцию пользователей,
скрытие внутренних ID и параллельность разных пользователей.

Для запуска без Docker задайте переменные окружения и `DATA_DIR=./data`, затем выполните:

```bash
python bot.py
```

## Структура

- `bot.py` — Telegram, OpenAI Responses/Image API, сценарии, промпты и параллельный dispatcher.
- `core.py` — SQLite, миграции, нормализация фото и проверка выбранных комплектов.
- `tests/test_bot.py` — сценарные проверки без сети.
